# ブログの使いやすさを直す（設計・短い版）

作成：2026-11-16。運営者が 1〜4 の修正を OK し、2 は自動、4 の下のバーは「消す」を選んだ。

## なぜ直すか

2026-11-16 にスマホ（幅 390）と PC（幅 1280）で本番を試した。読者（スマホで X から来る開業準備中の人）が、長い記事の中で迷う・読み終えたら帰る・押した先が行き止まり・スマホで本文が見える場所が狭い、の 4 つが見つかった。

## ゴール

1. **目次**：長い記事で、知りたい所へ 1 回で飛べる。
2. **同じテーマの記事**：読み終えたあと、次に読む記事が同じテーマで 3 本出る。
3. **行き止まりをなくす**：押した先が「準備中」になるリンクを出さない。
4. **スマホのヘッダーを低く**：記事を開いた 1 画面目に本文が見える。

## しないこと

- デザイン（色・文字・カードの形）の作り直しはしない。11/12 の見直し（`2026-11-12-pos-focus-redesign-design.md`）の形を守る。
- トップの新着の数・カテゴリのタブ（調べた 5・6）は今回は直さない。
- 記事の本文は直さない。

## 作り方（決めたこと）

### 1. 目次
- 記事の h2 から、ビルドのときに自動で作る。h2 に id を付け、目次はそこへのリンクにする。
- h2 が 3 つ以上ある記事だけに出す。置き場所は記事の見出し部分（タイトル・タグ）のすぐ下。最初から開いた形。
- 本文の途中に差し込む比較表などのブロックの見出し（products-heading）は目次に入れない（本文の h2 だけ）。
- 同じ見出しが 2 つあっても id が重ならないようにする。

### 2. 同じテーマの記事（自動）
- 記事の最後、「前の記事・次の記事」の上に 3 本出す。
- 選び方：ほかの記事ごとに「重なるタグの数」を数え、同じカテゴリなら少し足す。点の高い順、同点なら新しい順に 3 本。点が 0 の記事は出さない。
- フロントマターに `related:`（slug の並び）があれば、それを先に出し、足りない分を自動で埋める。
- 公開していない記事（scheduled/）は出さない（今の一覧と同じく、content/posts の記事だけを使う）。

### 3. 行き止まり
- AI無料POSレジ診断が受付前（`CONSULT_AVAILABLE` が false）のあいだは、フッターのリンクと、トップの「準備中です」の文を出さない。
- /about の文中のリンクは、受付前は文字だけにする（「現在は準備中です」の説明は残す）。
- お問い合わせ：運営者の返事待ち（フォームを受付に戻すか、リンクを隠すか）。受付に戻すなら、コードは変えない。

### 4. スマホのヘッダーと下のバー
- スマホ（幅が狭いとき）だけ：1 行目＝ロゴと虫めがね、2 行目＝メニュー 4 つを 1 行。Instagram と X のアイコンはヘッダーから外す（フッターにリンクがある）。目安の高さは約 110px。
- 下の固定のバー（サイトマップ・記事を探す・トップ・↑）は消し、右下に小さな「↑」（ページの上へ）だけを残す。
- PC の見た目は変えない。

## 守ること

- 今のテスト（`npm test`）とビルド（`npm run build`）を通す。
- 作業用ブランチ `ux-improve`（C:\dev\markdown-blog-ux）で作り、main に入れるのは運営者の OK のあと。
- 直したあと、スマホと PC の画面を撮って運営者に見せる。

## 作る人にまかせること

- 目次・関連記事・↑ボタンの細かい見た目（今のブログの色と線に合わせる）。
- 同じカテゴリに足す点の大きさ（タグ 1 つ分より小さく）。
