# AI無料POSレジ診断の設置手順

サイトの `/consult` から開く Google フォームに、`ai-consult.gs` を付けて動かす。
相談が届くと、AI が回答の下書きを作り、**Gmail の下書き**に入れる。運営者が読んで直してから送信する（自動では送らない）。

| エージェント | 役割 | いつ動くか |
| --- | --- | --- |
| Agent 1：店舗ITインフラ専門AI | 相談を分析し、調査結果（問題概要・原因候補・切り分け・推奨対応・ベンダー確認・信頼度）を書く。対象か対象外かも判定する。調査結果は運営者への通知にだけ入れる | 相談が届くたび |
| Agent 2：運用ドキュメント担当 | 相談者向けの手順書を作り、Agent 3 に渡す | Agent 1 が「手順書：必要」と判定したときだけ |
| Agent 3：ITコンサルタント | Agent 1 の調査結果と Agent 2 の手順書を受け取り、相談者への回答本文を敬語で書く（Gmail の下書きに入れる） | 相談が届くたび |
| Agent 1：店舗ITインフラ専門AI（月次リサーチ） | 専門分野の機器の新しい情報をネットで調べ、「月次リサーチ」シートに残す。A：不具合・障害・更新・サポート終了（Agent 3 が参考にする）、B：新機能・料金や手数料の変更・補助金・消費税などの制度（ブログの記事のネタ）。調べる対象はブログでよく取り上げているものに合わせ、優先の順に、①POS（Airレジ・スマレジ・Square）②キャッシュレス決済 ③補助金・消費税・インボイス・不正利用 ④レジの iPad の OS ⑤周辺機器 ⑥業種向けの機能・会計ソフト連携。①〜④は毎回、⑤⑥は検索の回数が残ったとき。最後に「直したほうがよさそうな記事」と「記事のネタの候補」（3 つまで）を出す。ブログの記事が増えたら、`RESEARCH_PROMPT` の「ブログにある主な記事」も直す | 毎月1日 7:00 |

受け付ける相談：POSシステム・決済端末、ハンディターミナル・バーコードリーダー・モバイルスキャナー、レシートプリンター・ラベルプリンター・キャッシュドロア、業務用の Android 端末（Android Enterprise を含む）、ネットワーク機器（Wi-Fi アクセスポイント・ルーター・スイッチ・LAN 配線）。
受け付けない相談：Windows PC・Microsoft 365・Intune、集客・経営全般、税金や法律の個別の判断。対象外の相談には、お断りの下書きを作る。

## 1. Google フォームを作る

**ブログ用の Google アカウント**で、新しいフォームを作る（個人のアカウントで作ると、回答メールが個人のアドレスから届いてしまう）。質問のタイトルは、`ai-consult.gs` の `CONFIG.fields` と**一字一句同じ**にする。

**おすすめ：`create-form.gs` で自動で作る**（下の表の質問・説明・必須・同意のチェック・回答のスプレッドシートまで、1 回の実行でそろう）

1. ブログ用の Google アカウントで https://script.google.com を開き、「新しいプロジェクト」
2. 最初からある中身を消して `create-form.gs` の中身を全部貼り、保存する
3. 関数の選択で `createConsultForm` を選んで「実行」。初回は権限の確認が出るので、ブログ用のアカウントで許可する
4. 「実行ログ」に出る 3 つの URL（フォームの編集・回答用・回答のスプレッドシート）を控える
5. ヘッダー画像だけはスクリプトで付けられないので、フォームの編集画面の「テーマをカスタマイズ」→「ヘッダー」で付ける
6. 作り終わったら、この「新しいプロジェクト」はもう使わない（消してもよい）。2 回実行するとフォームが 2 つできる

手で作る場合は、下の表のとおりに作る。フォームは 4 つのセクション（ページ）に分ける。「何を診断しますか」は「回答に応じてセクションに移動」にし、POSレジ選びのセクションのあとは「最後のセクションに移動」にする（トラブルのセクションを飛ばす）。

| セクション | 質問のタイトル | 形式 | 必須 | 選択肢 |
| --- | --- | --- | --- | --- |
| 1. 最初 | メールアドレス | 記述式（回答の検証：テキスト → メールアドレス） | ○ | |
| 1. 最初 | お店の種類 | ラジオボタン | ○ | カフェ・飲食店 / 美容・サロン / アパレル・雑貨 / キッチンカー / 開業準備中 / その他 |
| 1. 最初 | 何を診断しますか | ラジオボタン | ○ | POSレジを選びたい（開業前・入れかえ）→ 2 へ / 今の機器のトラブル・使い方 → 3 へ |
| 2. POSレジ選び | 使いたいPOSレジ | チェックボックス | | Airレジ / スマレジ / Square / まだ決めていない / その他（自由記入） |
| 2. POSレジ選び | POSレジは初めてですか | ラジオボタン | ○ | 初めて使う / 今のレジから入れかえる |
| 2. POSレジ選び | レジに使う端末 | ラジオボタン | ○ | iPad / iPhone / 専用のPOSレジ（レジ用の機械） / まだ決めていない |
| 2. POSレジ選び | レシートプリンター | ラジオボタン | ○ | もう持っている / これから買う / 使わない（紙のレシートを出さない） / 分からない |
| 2. POSレジ選び | お店の大きさ | ラジオボタン | ○ | 1人で営業する / 2〜3人 / 4人以上 |
| 2. POSレジ選び | 1日の会計の数 | ラジオボタン | ○ | 30件くらいまで / 30〜100件 / 100件より多い / 分からない（開業前） |
| 2. POSレジ選び | 営業の場所 | ラジオボタン | ○ | お店（店舗）だけ / お店とイベント出店 / キッチンカー・移動販売・イベント出店だけ |
| 2. POSレジ選び | レジのまわり | チェックボックス | ○ | 水がかかる・ぬれた手でさわる / 油・粉・ほこりで汚れる / 屋外で使う（雨・日差し） / 電源やインターネットがない場所で使う / 特になし |
| 2. POSレジ選び | 最初にかけられる費用 | ラジオボタン | | 5万円くらいまで / 5万〜15万円 / 15万円より多い / まだ決めていない |
| 2. POSレジ選び | 大事にしたいこと | チェックボックス | | 月々の料金が安い / 決済手数料が安い / 操作がかんたん / 在庫の管理 / 予約・お客様の管理 / 会計ソフトとの連携 / ネットがなくても会計できる / 困ったときのサポート |
| 3. トラブル | 診断してほしい機器 | ラジオボタン | ○ | POSレジ・決済端末 / ハンディターミナル・スキャナー / プリンター・キャッシュドロア / 業務用Android端末 / ネットワーク機器 / その他 |
| 3. トラブル | いつから起きていますか | 記述式 | | 説明：例）今日の昼から、3日前から、ときどき |
| 3. トラブル | 画面やランプの表示 | 段落 | | 説明：エラーの文字やコードは、そのまま書き写してください。ランプの色や点滅のしかたも |
| 3. トラブル | 機器のメーカー・機種名 | 記述式 | | 説明：本体の裏や底のラベルに書いてあります。分からなければ空欄で大丈夫です |
| 3. トラブル | 機器のつなぎ方 | ラジオボタン | | 単体で使っている / POSレジとつないでいる / 分からない |
| 3. トラブル | 起きている範囲 | ラジオボタン | | いつも起きる / ときどき起きる・一部だけで起きる（特定のカードや商品など） / 分からない |
| 3. トラブル | 機器の台数 | ラジオボタン | | 1台だけ使っている / 複数台あり、すべてで起きる / 複数台あり、一部だけで起きる |
| 4. 最後 | 困っていること・知りたいこと | 段落 | ○ | |
| 4. 最後 | 確認事項 | チェックボックス | ○ | 「回答は AI が作成した下書きを、運営者が確認してお送りすることに同意します」「氏名・住所・電話番号・カード番号・パスワードなどは書きません」 |

- フォームの説明に、`/consult` のページと同じ注意書き（返信まで数日かかること、個人情報を書かないこと）を入れる
- 「設定」→「回答」で、メールアドレスの収集は「収集しない」にする（上の質問で聞くため）
- ヘッダー画像は `デスクトップ\SNS投稿\ai-consult-form-header.png`

## 2. 回答のスプレッドシートを作り、スクリプトを貼る

1. フォームの「回答」タブ →「スプレッドシートにリンク」で新しいシートを作る（`create-form.gs` で作った場合は作成済み。実行ログのスプレッドシートの URL を開く）
2. シートを開き、「拡張機能」→「Apps Script」
3. 最初からある `コード.gs` の中身を消し、`ai-consult.gs` の中身を全部貼って保存する

## 3. API キーを入れる（コードには書かない）

1. Claude の API キーを用意する（Claude Console の「API Keys」で作る）。使いすぎを防ぐため、Console で月の利用上限も設定しておく
2. Apps Script の左の歯車「プロジェクトの設定」→ 下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
3. プロパティ：`ANTHROPIC_API_KEY`、値：API キー

## 4. 動作を確かめる

1. エディタの上の関数の選択で `testAskClaude`（トラブルの相談）を選び、「実行」。POS レジ選びの相談は `testAskClaudeSelect` で試せる（どちらも 1 回 約 $0.4）
2. 初回は権限の確認が出るので、ブログ用のアカウントで許可する
3. 「実行ログ」に「判定：対象」と、Agent 1 の調査結果・Agent 3 の回答本文が出れば OK
4. 関数の選択で `monthlyResearch` を選んで「実行」し、シートに「月次リサーチ」のタブができて結果が入ることを確かめる

## 5. トリガー（自動で動くきっかけ）を2つ作る

エディタの関数の選択で `setupTriggers` を選んで「実行」すると、次の2つが1回でできる（何度実行しても2つのまま）。手で作る場合は、左の時計のアイコン「トリガー」→「トリガーを追加」で、次の2つを作る。

| 実行する関数 | イベントのソース | 種類 |
| --- | --- | --- |
| `onFormSubmit` | スプレッドシートから | フォーム送信時 |
| `monthlyResearch` | 時間主導型 | 月ベースのタイマー → 1日 → 午前7時〜8時 |

フォームに自分でテストの相談を送り、次を確かめる。
- Gmail の「下書き」に回答が入っている
- 運営者あてに「[AI診断] 回答の下書きを確認してください」が届く（Agent 1 の調査結果もここに入る）
- シートの右端の「AI診断の状態」に「下書き作成（対象）・未送信」と出る

## 6. サイトにつなぐ

1. フォームの「送信」→ リンクのアイコンで URL をコピー（`.../viewform` で終わるもの）
2. Vercel の Settings → Environment Variables に `NEXT_PUBLIC_CONSULT_FORM_URL` として追加し、再デプロイする
3. `/consult` にフォームが表示されることを確かめる

## 作業代行の案内

顔出し・電話をしない方針のため、個別面談はしない。代わりに、対象の相談の回答の最後に、有料の作業代行（`/services`）の案内を入れる。作業代行の受付を始めたら、`ai-consult.gs` の `CONFIG.servicesUrl` に `https://www.mise-register.com/services` を入れる。空のあいだは、この文言を入れない（通知メールにその旨が出る）。

## ふだんの運用

- 通知が来たら、Gmail の「下書き」を開いて内容を確かめ、必要なら直してから送信する
- 送ったら、シートの「AI診断の状態」を「送信済み」に書き換える
- AI の回答がまちがっていたら、直して送る。よくあるまちがいは、エージェントの指示（`AGENT1_PROMPT`・`AGENT3_PROMPT`）に注意を足す
- 1日の上限（`CONFIG.dailyLimit`、初期値 20 件）を超えた相談は AI に回さず、通知だけ届く。手で返信する
- 1か月の API 料金の上限（`CONFIG.monthlyBudgetUsd`、初期値 5 ドル）に近づくと、相談を AI に回さず、通知だけ届く。手で返信する。月次リサーチも、相談の分を残すために休む。使った額は、API の応答の usage（トークン数とネット検索の回数）と `CONFIG.prices` の料金から計算して、スクリプト プロパティの `spendMonth`・`spendUsd` に記録する（月が変わると 0 から数え直す）。通知メールに今月の額が出る。正確な額は Claude Console で確かめる
- 同じメールアドレスからの相談は、1か月に3回まで（`CONFIG.monthlyLimitPerEmail`）。4回目からは AI に回さず、通知だけ届く。回答シートの「タイムスタンプ」と「AI診断の状態」（下書き作成…）で数えるので、この2つの列は消さない

## 個人情報の伏せ字

相談者がうっかり個人情報を書いても AI（Claude）に送らないように、AI に送る前に、形の決まった個人情報を「［伏せ字］」に置き換える（`CONFIG.maskPersonalInfo`、初期値 `true`）。

| 伏せるもの | 例 |
| --- | --- |
| 電話番号（0 か +81 で始まる 10〜11 けた） | 03-1234-5678、０９０－１２３４－５６７８ |
| メールアドレス | tanaka@example.com |
| カード番号らしい数字（13〜19 けた） | 4111 1111 1111 1111 |
| 郵便番号 | 〒150-0001、150-0001 |
| 番地のある住所 | 東京都渋谷区神宮前1-2-3、大阪市北区梅田3丁目4番5号 |
| パスワード・暗証番号の値 | 「パスワードは abc123」の abc123 |

- 機種名（TM-T88VI、400-SCN059）やエラーコード（E-05）、IP アドレス、日付は伏せない
- **氏名や、番地のない住所は見つけられない**。フォームの「書かないで」のお願いは続ける
- 13 けた以上の数字（端末のシリアル番号など）は、カード番号と区別できないので伏せる
- 元の文はシートに残る。AI に送るもの・通知メールに入れるものだけが伏せ字になる
- 伏せた部分があると、通知メールに「個人情報らしい部分を伏せてから AI に送りました（電話番号 1件…）」と出て、シートの「AI診断の状態」に「伏せ字あり」と付く。下書きに個人情報が残っていないか確かめてから送る
- AI への指示にも、「［伏せ字］の内容を推測しない」「検索語に名前・連絡先・住所を入れない」を入れている
- 動きを確かめるときは、エディタで `testMaskPersonalInfo` を実行して「実行ログ」を見る（AI には送らない）

## エラーコードの調査

相談に「画面やランプの表示」が書かれていたら、Agent 1 がネット検索（最大 `CONFIG.errorCodeMaxSearches` 回）でエラーコードの意味を調べ、出典の URL と一緒に調査結果の「■ エラーコードの調査」に書く。メーカーの公式情報を優先し、確かめられなければ推測しない。Agent 3 は、出典のメーカー名を添えて相談者に伝える。運営者は、通知メールで出典の URL を開いて確かめてから送る。

## 費用の目安（Claude Opus 5.5）

- 相談 1 件：エラーの表示が書かれた相談（エラーコードの調査あり）は、2026年11月2日の `testAskClaude` で約 $0.4 だった（このときはネット検索 4 回まで）。いまは検索を 2 回まで（`CONFIG.errorCodeMaxSearches`）にしているので、それより少し安くなる見込み。検索で読んだページの文章も入力として数えられるため、検索の回数が料金に効く
- 月次リサーチ：ネット検索 10 回まで（`CONFIG.researchMaxSearches`）。1 回 約 $1 前後（見込み。実際の額は通知メールで確かめる）
- 月の上限 $5 の場合：月次リサーチの分を引いて、相談は月に 10〜15 件くらいまで AI に回せる見込み。実際の額は、通知メールの「今月の API 料金」とスクリプト プロパティの `spendUsd` で見る
- 正確な金額は Claude Console の「Usage」で確かめる
- Gmail・Google フォーム・Apps Script：無料（Apps Script のメール送信は 1日100通まで。通知メールがこれに数えられる）
