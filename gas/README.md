# AI相談デスクの設置手順

サイトの `/consult` から開く Google フォームに、`ai-consult.gs` を付けて動かす。
相談が届くと、AI が回答の下書きを作り、**Gmail の下書き**に入れる。運営者が読んで直してから送信する（自動では送らない）。

| エージェント | 役割 | いつ動くか |
| --- | --- | --- |
| Agent 1：店舗ITインフラ専門AI | 相談を分析し、調査結果（問題概要・原因候補・切り分け・推奨対応・ベンダー確認・信頼度）を書く。対象か対象外かも判定する。調査結果は運営者への通知にだけ入れる | 相談が届くたび |
| Agent 2：運用ドキュメント担当 | 相談者向けの手順書を作り、Agent 3 に渡す | Agent 1 が「手順書：必要」と判定したときだけ |
| Agent 3：ITコンサルタント | Agent 1 の調査結果と Agent 2 の手順書を受け取り、相談者への回答本文を敬語で書く（Gmail の下書きに入れる） | 相談が届くたび |
| Agent 1：店舗ITインフラ専門AI（週次リサーチ） | 専門分野の機器の新しい情報（不具合・更新・サポート終了）をネットで調べ、「週次リサーチ」シートに残す。Agent 3 が参考にする | 毎週月曜 7:00 |

受け付ける相談：POSシステム・決済端末、ハンディターミナル・バーコードリーダー・モバイルスキャナー、レシートプリンター・ラベルプリンター・キャッシュドロア、業務用の Android 端末（Android Enterprise を含む）、ネットワーク機器（Wi-Fi アクセスポイント・ルーター・スイッチ・LAN 配線）。
受け付けない相談：Windows PC・Microsoft 365・Intune、集客・経営全般、税金や法律の個別の判断。対象外の相談には、お断りの下書きを作る。

## 1. Google フォームを作る

**ブログ用の Google アカウント**で、新しいフォームを作る（個人のアカウントで作ると、回答メールが個人のアドレスから届いてしまう）。質問のタイトルは、`ai-consult.gs` の `CONFIG.fields` と**一字一句同じ**にする。

| 質問のタイトル | 形式 | 必須 | 選択肢 |
| --- | --- | --- | --- |
| メールアドレス | 記述式（回答の検証：テキスト → メールアドレス） | ○ | |
| お店の種類 | ラジオボタン | ○ | カフェ・飲食店 / 美容・サロン / アパレル・雑貨 / キッチンカー / 開業準備中 / その他 |
| 相談の種類 | ラジオボタン | ○ | POSレジ・決済端末 / ハンディターミナル・スキャナー / プリンター・キャッシュドロア / 業務用Android端末 / ネットワーク機器 / その他 |
| 相談内容 | 段落 | ○ | |
| いつから起きていますか | 記述式 | | 説明：例）今日の昼から、3日前から、ときどき |
| 画面やランプの表示 | 段落 | | 説明：エラーの文字やコードは、そのまま書き写してください。ランプの色や点滅のしかたも |
| 機器のメーカー・機種名 | 記述式 | | 説明：本体の裏や底のラベルに書いてあります。分からなければ空欄で大丈夫です |
| 機器のつなぎ方 | ラジオボタン | | 単体で使っている / POSレジとつないでいる / 分からない |
| 起きている範囲 | ラジオボタン | | いつも起きる / ときどき起きる・一部だけで起きる（特定のカードや商品など） / 分からない |
| 機器の台数 | ラジオボタン | | 1台だけ使っている / 複数台あり、すべてで起きる / 複数台あり、一部だけで起きる |
| 確認事項 | チェックボックス | ○ | 「回答は AI が作成した下書きを、運営者が確認してお送りすることに同意します」「氏名・住所・電話番号・カード番号・パスワードなどは書きません」 |

- フォームの説明に、`/consult` のページと同じ注意書き（返信まで数日かかること、個人情報を書かないこと）を入れる
- 「設定」→「回答」で、メールアドレスの収集は「収集しない」にする（上の質問で聞くため）
- ヘッダー画像は `デスクトップ\SNS投稿\ai-consult-form-header.png`

## 2. 回答のスプレッドシートを作り、スクリプトを貼る

1. フォームの「回答」タブ →「スプレッドシートにリンク」で新しいシートを作る
2. シートを開き、「拡張機能」→「Apps Script」
3. 最初からある `コード.gs` の中身を消し、`ai-consult.gs` の中身を全部貼って保存する

## 3. API キーを入れる（コードには書かない）

1. Claude の API キーを用意する（Claude Console の「API Keys」で作る）。使いすぎを防ぐため、Console で月の利用上限も設定しておく
2. Apps Script の左の歯車「プロジェクトの設定」→ 下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
3. プロパティ：`ANTHROPIC_API_KEY`、値：API キー

## 4. 動作を確かめる

1. エディタの上の関数の選択で `testAskClaude` を選び、「実行」
2. 初回は権限の確認が出るので、ブログ用のアカウントで許可する
3. 「実行ログ」に「判定：対象」と、Agent 1 の調査結果・Agent 3 の回答本文が出れば OK
4. 関数の選択で `weeklyResearch` を選んで「実行」し、シートに「週次リサーチ」のタブができて結果が入ることを確かめる

## 5. トリガー（自動で動くきっかけ）を2つ作る

左の時計のアイコン「トリガー」→「トリガーを追加」で、次の2つを作る。

| 実行する関数 | イベントのソース | 種類 |
| --- | --- | --- |
| `onFormSubmit` | スプレッドシートから | フォーム送信時 |
| `weeklyResearch` | 時間主導型 | 週ベースのタイマー → 毎週月曜日 → 午前7時〜8時 |

フォームに自分でテストの相談を送り、次を確かめる。
- Gmail の「下書き」に回答が入っている
- 運営者あてに「[AI相談] 回答の下書きを確認してください」が届く（Agent 1 の調査結果もここに入る）
- シートの右端の「AI相談の状態」に「下書き作成（対象）・未送信」と出る

## 6. サイトにつなぐ

1. フォームの「送信」→ リンクのアイコンで URL をコピー（`.../viewform` で終わるもの）
2. Vercel の Settings → Environment Variables に `NEXT_PUBLIC_CONSULT_FORM_URL` として追加し、再デプロイする
3. `/consult` にフォームが表示されることを確かめる

## 作業代行の案内

顔出し・電話をしない方針のため、個別面談はしない。代わりに、対象の相談の回答の最後に、有料の作業代行（`/services`）の案内を入れる。作業代行の受付を始めたら、`ai-consult.gs` の `CONFIG.servicesUrl` に `https://www.mise-register.com/services` を入れる。空のあいだは、この文言を入れない（通知メールにその旨が出る）。

## ふだんの運用

- 通知が来たら、Gmail の「下書き」を開いて内容を確かめ、必要なら直してから送信する
- 送ったら、シートの「AI相談の状態」を「送信済み」に書き換える
- AI の回答がまちがっていたら、直して送る。よくあるまちがいは、エージェントの指示（`AGENT1_PROMPT`・`AGENT3_PROMPT`）に注意を足す
- 1日の上限（`CONFIG.dailyLimit`、初期値 20 件）を超えた相談は AI に回さず、通知だけ届く。手で返信する
- 同じメールアドレスからの相談は、1か月に3回まで（`CONFIG.monthlyLimitPerEmail`）。4回目からは AI に回さず、通知だけ届く。回答シートの「タイムスタンプ」と「AI相談の状態」（下書き作成…）で数えるので、この2つの列は消さない

## エラーコードの調査

相談に「画面やランプの表示」が書かれていたら、Agent 1 がネット検索（最大 `CONFIG.errorCodeMaxSearches` 回）でエラーコードの意味を調べ、出典の URL と一緒に調査結果の「■ エラーコードの調査」に書く。メーカーの公式情報を優先し、確かめられなければ推測しない。Agent 3 は、出典のメーカー名を添えて相談者に伝える。運営者は、通知メールで出典の URL を開いて確かめてから送る。

## 費用の目安（Claude Opus 5.5）

- 相談 1 件：約 $0.10（Agent 1 と Agent 3 の2回）。手順書を作るときは約 $0.13（Agent 2 も入れて3回）。エラーの表示が書かれた相談は、エラーコードの調査で約 $0.03〜0.08 増える
- 週次リサーチ：1 回 約 $0.3（ネット検索の料金を含む）。月に約 $1.3
- 正確な金額は Claude Console の「Usage」で確かめる
- Gmail・Google フォーム・Apps Script：無料（Apps Script のメール送信は 1日100通まで。通知メールがこれに数えられる）
